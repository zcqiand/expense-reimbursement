# 财务报销系统 — 功能规格文档

> 本文档描述 财务报销系统 的所有功能特性、验收标准与测试策略。
> 与 [CLAUDE.md](../CLAUDE.md) 共同构成本仓的完整规范文档。

## 功能清单

### 报销单管理

| 功能名称       | 功能描述                       | 验收标准                                               |
| :------------- | :----------------------------- | :----------------------------------------------------- |
| 报销单提交     | 员工提交报销单，初始状态 DRAFT | POST /api/expense-reports 返回 201，status = DRAFT     |
| 报销单状态流转 | DRAFT → SUBMITTED → APPROVED | REJECTED → PAID                                       |
| 拒绝必填理由   | REJECTED 必须填写拒绝原因      | service 层强制校验，reason 为空抛 BusinessException    |
| 报销单列表查询 | 按员工/部门/状态筛选           | GET /api/expense-reports?status=SUBMITTED 返回对应列表 |

### 多级审批流

| 功能名称            | 功能描述                     | 验收标准                                          |
| :------------------ | :--------------------------- | :------------------------------------------------ |
| 一级审批（< 1000）  | 直属经理审批一次即通过       | 金额 500 订单 approve 一次 status = APPROVED      |
| 两级审批（≥ 1000） | 部门经理 + 财务总监依次审批  | 金额 2000 订单 approve 两次才 PAID，一次 REJECTED |
| 审批历史记录        | 每次审批记录审批人/时间/结果 | 订单详情 API 返回 approvalHistory 数组            |

### OCR 票据识别

| 功能名称    | 功能描述                            | 验收标准                                   |
| :---------- | :---------------------------------- | :----------------------------------------- |
| 多语言 OCR  | Tesseract OCR 识别发票图片          | 图片输入返回结构化字段（金额/日期/发票号） |
| Mock 降级   | OCR 服务不可用时返回 Mock 数据      | OCR service 异常不影响报销单提交           |
| 零 Key 依赖 | 纯本地 Tesseract，CI 不需要 API Key | `docker compose up` 后 OCR 功能开箱可跑  |

### 结构化审批意见生成（LLM）

> v2 起本节功能的修复循环内核已整体迁入 Python sidecar（`agent/`，LangGraph
> 生成图，见仓 README 架构段）；Spring 侧只做前置校验、上下文组装、经 HTTP
> 薄客户端调用与落库。等价锚（总调用 ≤3 / extractJson 边界 / 三字段非空白 /
> 回喂措辞）钉在 `agent/tests/test_graph.py`。

| 功能名称         | 功能描述                                    | 验收标准                                       |
| :--------------- | :------------------------------------------ | :--------------------------------------------- |
| JSON Schema 输出 | LLM（OpenAI 兼容，可配模型）返回结构化 JSON | 响应符合 ApprovalOpinion JSON Schema           |
| 验证-修复循环    | Schema 验证失败自动重试（最多 3 次）        | 第一次返回 invalid JSON 时第二次返回修复后结果 |
| 测试可打桩       | `OpinionAgentClient` 端口可注入 mock 实现   | service 层测试不依赖真实 API                   |
| 零伪代码         | 禁止 throw UnsupportedOperationException    | 代码审查无未实现方法                           |

### 报表聚合

| 功能名称   | 功能描述                           | 验收标准                                      |
| :--------- | :--------------------------------- | :-------------------------------------------- |
| 按部门汇总 | 聚合各部门报销总额/单数/平均金额   | GET /api/reports/by-department 返回部门维报表 |
| 按状态筛选 | 按 APPROVED/REJECTED/PAID 状态筛选 | 报表数据与实际订单状态一致                    |
| 时间维度   | 支持按月份/季度筛选                | 时间范围查询返回结果与时间窗匹配              |

### 审计日志

| 功能名称     | 功能描述                               | 验收标准                           |
| :----------- | :------------------------------------- | :--------------------------------- |
| 操作记录     | 记录所有状态变更操作用户/时间/变更前后 | audit_log 表有完整变更流水         |
| 权限矩阵测试 | 32 种权限组合有测试覆盖                | 测试运行后 coverage 报告含权限分支 |

### 数据库迁移（Flyway）

| 功能名称      | 功能描述                              | 验收标准                                                      |
| :------------ | :------------------------------------ | :------------------------------------------------------------ |
| 初始 schema   | V1__init.sql 创建全部表结构           | 容器启动后查询到 expense_report/approval_history/audit_log 表 |
| 禁止 DDL auto | application.yml 中无 ddl-auto: update | 配置审查确认无 hibernate ddl-auto                             |

### 前端 UI

| 功能名称         | 功能描述                        | 验收标准                                         |
| :--------------- | :------------------------------ | :----------------------------------------------- |
| 工作台 Dashboard | 展示待审批/已审批/报销统计      | Dashboard.tsx 有数据展示区域                     |
| 报销单提交表单   | SubmitForm 登账 + 一键提交审批  | POST /api/v1/expense-reports 成功                |
| 审批界面         | SUBMITTED 列表审批 + APPROVED 付款 | Approval.tsx 有 approve/reject 按钮            |
| 票据上传入口     | 工作台行详情上传图片触发 OCR    | 上传后展示 Receipt（ocrStatus + ocrText）        |
| AI 审批意见展示  | 生成三段意见卡（结论/依据/建议） | opinion 接口成功后意见卡可见                    |
| JWT 认证         | REST API 带 JWT token           | 后端未实现该能力，前端暂不做（README 有标注）    |

### 容器编排（Docker Compose）

| 功能名称   | 功能描述                               | 验收标准                                     |
| :--------- | :------------------------------------- | :------------------------------------------- |
| 三服务启动 | postgres + backend + frontend 一键启动 | `docker compose up -d` 全部服务 running    |
| 网络互通   | frontend → backend → postgres 连通   | curl localhost:8080/swagger-ui.html 返回 200 |
